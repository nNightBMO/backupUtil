# Вклад в проект

Спасибо за интерес! Ниже — как предложить изменение.

## Перед началом

- Для крупных изменений сначала откройте issue и опишите задачу.
- Утилита работает с чужими данными и секретами, поэтому приоритеты такие: **не потерять данные → не раскрыть секреты → удобство**.
  Изменения, ослабляющие защиту (права файлов, шифрование, подтверждения), будут отклонены без веской причины.

## Окружение

```bash
python -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
sudo pacman -S --needed zstd pv age shellcheck     # или аналоги вашего дистрибутива
```

## Проверки

```bash
python -m pytest -q
bash tests/smoke.sh
shellcheck -x -S warning backup.sh restore.sh tests/smoke.sh
```

CI запускает то же самое. Новые возможности сопровождайте тестами: для TUI — сценарий на Textual Pilot, для
загрузчика — подставной клиент (реальный Telegram в автотестах не используется), для форматов — интеграционный тест.

## Правила

- Источники только читаются: никакого кода, который пишет или удаляет внутри архивируемых директорий.
- Операции, удаляющие данные, должны быть выключены по умолчанию и требовать подтверждения.
- Форматы `backup.conf`, `backup.env`, `telegram.toml`, `MANIFEST.txt`, `*.sha256` совместимы между `backup.sh`,
  `tg_upload.py` и `bu_config.py`: меняя один, меняйте остальные и тесты.
- Секреты, реальные пути и данные в тестах, документации и скриншотах недопустимы.
- Новые файлы проекта нужно явно добавить в белый список `.gitignore`.
- Сообщения для пользователя — на русском, код и комментарии — по смыслу; стиль shell-скриптов — как в существующих.

## Pull request

1. Ветка от `main`, понятное название.
2. Описание: что и зачем, как проверить, затронуты ли форматы файлов.
3. Обновите `CHANGELOG.md` и документацию, если изменилось поведение.
