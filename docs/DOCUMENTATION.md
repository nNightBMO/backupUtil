## 1. Обзор и архитектура

| Компонент | Язык | Назначение |
|---|---|---|
| `backup.sh` | bash | сборка архивов, сухой запуск, проверка места, запуск остальных частей |
| `restore.sh` | bash | проверка `sha256`, склейка томов, распаковка |
| `tg_upload.py` | Python (Telethon) | вход в аккаунт, список групп и топиков, загрузка, журнал, метки |
| `tui.py` | Python (Textual) | интерфейс настройки и запуска |
| `bu_config.py` | Python (stdlib) | чтение и запись конфигов; общий слой для TUI и тестов |

Компоненты не зависят друг от друга по коду: `backup.sh` и `tg_upload.py` читают конфиги самостоятельно, а TUI лишь редактирует те же файлы и запускает `backup.sh`. Поэтому всё, что делает TUI, можно сделать руками, и наоборот. Совпадение форматов проверяют интеграционные тесты.

Поток данных одной директории:

```
источник ─► tar ─► zstd ─► [age] ─► split ─► тома в <рабочая папка>/<имя>/
                                              │
                                              ├─ <имя>.sha256   sha256 каждого тома
                                              └─ MANIFEST.txt   описание набора
                                                       │
                              tg_upload.py ────────────▼
                  топик <имя>: тома → sha256 → MANIFEST → метка
```

## 2. Установка

**Зависимости**

| Пакет | Зачем | Обязателен |
|---|---|---|
| bash 4.4+, GNU `tar`, `coreutils`, `util-linux` (`flock`) | сборка и проверки | да |
| `zstd` | сжатие | да |
| Python 3.11+ | `tg_upload.py`, `tui.py` (нужен `tomllib`) | для Telegram и TUI |
| `pv` | прогресс в процентах | нет |
| `age` | шифрование | нет |
| `sudo` | чтение системных путей | нет |

```bash
# Arch Linux
sudo pacman -S --needed zstd age pv python tar

git clone https://github.com//backupUtil.git && cd backupUtil
python -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Если рядом лежит `.venv`, скрипты используют его автоматически; иначе берётся системный `python3`. Современные дистрибутивы запрещают `pip install` в системный Python (PEP 668), поэтому нужен venv.

Установка включает Telethon (MTProto-клиент), Textual (TUI) и необязательный `cryptg` (ускоряет шифрование протокола).

## 3. Рабочая папка и раскладка файлов

Рабочая папка — это папка, где лежат скрипты. Архивы, логи, состояние и секреты хранятся там же.

```
backupUtil/
├── backup.sh  restore.sh  tg_upload.py  tui.py  bu_config.py     # код
├── backup.conf.example  backup.env.example  telegram.toml.example # шаблоны (в git)
├── excludes.default.txt                                           # исключения по умолчанию (в git)
├── docs/  tests/  .github/                                        # проект
│
├── backup.conf          # ваш список директорий            (не в git)
├── backup.env           # ваши настройки backup.sh, 600    (не в git)
├── telegram.toml        # api_id/api_hash/группа/топики, 600 (не в git, СЕКРЕТ)
├── excludes.txt         # ваши исключения, если правили    (не в git)
├── backup.log           # журнал работы                    (не в git)
├── .secrets/            # сессия Telegram, ключ age, 700   (не в git, СЕКРЕТ)
├── .state/              # журнал выгрузки, номер autoback, блокировка
├── .venv/
└── <имя>/               # архивы директорий                (не в git)
```

**Зарезервированные имена** папок архивов: `.secrets`, `.state`, `.venv`, `__pycache__`, `.git`, `.github`, `docs`, `tests`, `examples`. Если директория так называется, задайте другое имя: `~/docs | my-docs`.

**Белый список в `.gitignore`.** Корень проекта одновременно хранит данные, поэтому `.gitignore` игнорирует всё, кроме перечисленных файлов проекта. Дополнительно запрещены `*.session`, `*.key`, `*.age`, `*.tar.zst*`, `telegram.toml`, `backup.env`. Ничего из личного нельзя добавить в репозиторий «случайно» через `git add .`.

## 4. Конфигурация

### 4.1. `backup.conf` — список директорий

```
путь [ | имя_папки [ | опции ] ]
```

| Поле | Значение |
|---|---|
| путь | `~` и `$HOME` раскрываются; допустимы пробелы и юникод; символ `|` недопустим |
| имя_папки | подпапка архивов и название топика; по умолчанию — последнее имя пути (`~/.config` → `.config`) |
| опции | через запятую: `encrypt`, `whole`, `sudo` |

Опции:

- `encrypt` — шифровать `age` перед нарезкой на тома;
- `whole` — вся директория одним архивом (по умолчанию каждый элемент — отдельный архив);
- `sudo` — читать через `sudo`. Для путей вне `$HOME` включается автоматически.

```
~/Documents
~/code
~/.config      |   | whole
~/.ssh         |   | encrypt,whole
~/.local/share | local-share
/etc           |   | whole
```

Строки, начинающиеся с `#`, и пустые строки игнорируются. Имена должны быть уникальны: если два пути оканчиваются одинаково, задайте имя явно. Директорию вне конфига можно указать в командной строке: это разовый запуск.

### 4.2. `backup.env` — настройки

Файл подключается командой `source`, поэтому значения не должны содержать кавычек, `` ` ``, `\` и `$(`. TUI проверяет это при сохранении.

| Ключ | По умолчанию | Описание |
|---|---|---|
| `VOLUME_SIZE` | `1800M` | размер тома (суффикс K/M/G); для Telegram строго меньше 2000M |
| `ZSTD_LEVEL` | `3` | уровень сжатия 1–19 |
| `SPLIT` | `1` | `0` — каждый архив одним файлом без нарезки |
| `ONE_FS` | `0` | `1` — не заходить в другие файловые системы и подтома (`tar --one-file-system`) |
| `AGE_RECIPIENT` | пусто | публичный ключ `age1…` |
| `AGE_RECIPIENTS_FILE` | пусто | файл с публичными ключами (вместо `AGE_RECIPIENT`) |

Приоритет значений: флаги командной строки → `backup.env` → значения по умолчанию.

### 4.3. Исключения

Файл `excludes.txt` (если его нет — `excludes.default.txt`) передаётся в `tar --exclude-from`. Файл разбит на секции:

```
[*]                 # правила для КАЖДОЙ директории
node_modules
__pycache__
*.pyc

[.config]           # правила только для директории с именем «.config»
Cache
Code Cache
GPUCache
```

Правила сопоставления:

- шаблон сравнивается с **концом пути**: `node_modules` исключает такую папку на любой глубине;
- `*` совпадает и через `/`;
- шаблон с пробелами пишется как есть: `Code Cache`;
- секция `[имя]` применяется, когда имя папки архива в точности равно `имя` (регистр важен);
- строки с `#` и пустые игнорируются.

> Общие правила в `[*]` намеренно консервативны. Имена вроде `Cache` или `target` могут быть обычными папками в ваших проектах, поэтому такие правила лежат в секциях конкретных директорий, например `[.config]`.

В режиме items элемент верхнего уровня, подпадающий под шаблон без `/`, вообще не получает архива.

Сама рабочая папка утилиты исключается автоматически, если оказывается внутри архивируемого источника (например, при бэкапе всего `$HOME`).

### 4.4. `telegram.toml`

Файл с правами `600`. Секции:

```toml
[telegram]
api_id   = 1234567                       # число
api_hash = "…"                           # секрет
group    = -1001234567890                # id, @username или точное название
session  = "/path/.secrets/tg.session"   # необязательно; по умолчанию .secrets/tg.session рядом со скриптами

[topics]                                 # необязательно: имя папки → id топика
"code" = 11

[autoback]
log_topic   = "Logs"                     # id или название топика логов
date_format = "%d.%m.%Y"                 # необязательно
log_message = "{date} autoback#{n}"      # необязательно
dir_message = "autoback#{n}"             # необязательно
```

`api_id` и `api_hash` выдаёт [my.telegram.org](https://my.telegram.org) в разделе *API development tools*.

## 5. Архивация

### 5.1. Конвейер

```
tar --create --acls --xattrs --numeric-owner --sparse --exclude-from=… -- <элемент>
  | [pv] | zstd -T0 -<уровень> | [age -r …] | split -b <размер> -d -a 3 - <имя>.tar.zst.
```

- Сохраняются права, владельцы (числовые), симлинки, xattr, ACL, разреженные файлы.
- Источник открывается только на чтение.
- Код возврата `tar` = 1 («файл изменился во время чтения») — предупреждение, архив считается созданным; ≥ 2 — ошибка.
- Файлы создаются с `umask 077`.

### 5.2. Режимы items и whole

| | items (по умолчанию) | whole (`--whole`, опция `whole`) |
|---|---|---|
| Архивов | по одному на каждый элемент верхнего уровня (файл или папка, включая скрытые) | один на директорию |
| Имя набора | `<элемент>.tar.zst.000…` | `<имя директории>.tar.zst.000…` |
| Содержимое | элемент вместе со своим именем (`./projA/…`) | содержимое директории (`./…`) |
| Плюсы | точечное восстановление, локальный ущерб от повреждения, мелкие тома | один набор, меньше сообщений |
| Минусы | много архивов у директорий с сотнями элементов | всё или ничего |

Восстановление в обоих режимах делается в **исходную директорию** (`--to <путь директории>`). Флаги `--items` / `--whole` в командной строке перекрывают опцию из конфига.

**Имена файлов архивов:** пробелы → `_`, ведущая точка → префикс `dot_` (`.config` → `dot_config`). При совпадении после преобразования к имени добавляется `~N`. Имена **папок** архивов (подпапок рабочей папки) остаются как есть, чтобы совпадать с названием топика.

### 5.3. Тома

`split -b 1800M -d -a 3` создаёт `NAME.tar.zst.000`, `.001`, … Размер тома задаёт `VOLUME_SIZE`. При `--single` / `SPLIT=0` архив — один файл `NAME.tar.zst`; если он больше лимита Telegram, загрузка такого файла будет отклонена.

С шифрованием имя получает `.age`: `NAME.tar.zst.age.000`.

### 5.4. Контрольные суммы и манифест

В каждой папке архивов лежит **один** файл `<имя>.sha256` в формате `sha256sum` (`хэш␠␠имя_файла`) на все тома всех архивов директории. Проверка вручную: `sha256sum -c <имя>.sha256`.

`MANIFEST.txt` — текст в формате `КЛЮЧ=значение`:

| Ключ | Значение |
|---|---|
| `DATE`, `HOST` | момент сборки (ISO 8601) и имя машины |
| `NAME`, `SOURCE` | имя папки и исходный путь |
| `MODE` | `items` или `whole` |
| `ENCRYPTED`, `SPLIT`, `VOLUME_SIZE`, `ZSTD_LEVEL` | параметры сборки |
| `RAW_BYTES` | оценка размера источника до сжатия |
| `ARCHIVE_BYTES` | суммарный размер томов |
| `SETS` | число архивов |
| `SHA256_FILE` | имя файла сумм |
| `FAILED` | элементы, которые не удалось собрать (если были) |
| `RESTORE`, `MANUAL` | команда восстановления утилитой и вручную |
| `SET=имя|томов|байт` | по строке на каждый архив |

### 5.5. sudo

Системные пути (вне `$HOME`) читаются через `sudo`. Повышенные права получает **только** `tar` (и `du`/`find` при оценке размера); `zstd`, `split` и запись файлов выполняются от вашего пользователя, поэтому архивы сразу принадлежат вам. Пароль запрашивается один раз, сессия `sudo` поддерживается фоновым процессом. Если в рабочей папке всё же окажется чужой файл, владелец возвращается командой `chown`.

### 5.6. Безопасная замена и ошибки

1. Архивы строятся во временной папке `.tmp.<pid>` внутри папки директории.
2. После успешной сборки удаляются тома пересобранных элементов и элементов, исчезнувших из источника; затем новые тома перемещаются на место.
3. Если часть элементов собрать не удалось, их **прежние тома остаются нетронутыми**, ошибка попадает в `MANIFEST.txt` (`FAILED`), код возврата — 1.
4. При смене режима (items ↔ whole) устаревшие наборы удаляются.

### 5.7. Оценка размера и место на диске

`--dry-run` показывает таблицу: сколько архивов и томов получится, сколько данных до сжатия и сколько места свободно. Оценка приблизительна: `du` считает исключения по-своему, а сжатие не учитывается. Перед началом проверяется, что «в худшем случае» (без сжатия) данные поместятся; `--no-space-check` отключает проверку для хорошо сжимаемых данных.

### 5.8. Прочее поведение

- Лог: `backup.log` (время, уровень, сообщение). Он содержит пути и имена, но не содержимое файлов.
- Блокировка `.state/lock` не даёт запустить две сборки одновременно.
- Без `pv` во время долгой упаковки раз в 20 секунд пишется, сколько уже записано.
- Прерывание (Ctrl+C) удаляет временные файлы и завершает работу с кодом 130.

## 6. Шифрование age

```bash
age-keygen -o .secrets/age.key         # напечатает «Public key: age1…»
chmod 600 .secrets/age.key
```

(То же делает кнопка «Сгенерировать ключ age» на вкладке «Параметры».) Публичный ключ записывается в `AGE_RECIPIENT`. Шифрование включается опцией `encrypt` у директории или флагом `--encrypt` для всего запуска.

- Сжатие выполняется **до** шифрования, поэтому размер архива не зависит от шифрования.
- Приватный ключ нужен только для восстановления. **Храните его отдельно от Telegram** (менеджер паролей, внешний носитель). Без ключа тома не открыть.
- Режим парольной фразы не поддерживается: он требует интерактивного ввода внутри конвейера.

## 7. Восстановление

```
restore.sh ПАПКА_С_ТОМАМИ (--to ПУТЬ | --original) [опции]
```

| Опция | Действие |
|---|---|
| `--to ПУТЬ` | куда распаковать (создаётся при необходимости; существующие файлы перезаписываются) |
| `--original` | распаковать в `SOURCE` из `MANIFEST.txt`; просит подтверждение (`-y` пропускает) |
| `--only ПОДСТРОКА` | только архивы, в имени которых есть подстрока; проверяются тоже только они |
| `--age-key ФАЙЛ` | приватный ключ для зашифрованных архивов |
| `--sudo` / `--no-sudo` | принудительно использовать или не использовать `sudo` при распаковке (по умолчанию `sudo` — вне `$HOME`) |
| `--verify-only` | только проверить `sha256` |
| `--test` | проверка `sha256` + прогон потока через `tar --list`, без записи на диск |

Порядок действий: проверка контрольных сумм → склейка томов каждого архива по порядку → расшифровка → распаковка. При несовпадении суммы распаковка не начинается.

Папку с томами можно скачать из Telegram вручную: нужны тома и `<имя>.sha256` (его утилита тоже загружает). `MANIFEST.txt` в этом случае нужен только для `--original`.

Ручное восстановление без утилиты:

```bash
sha256sum -c code.sha256
cat projA.tar.zst.[0-9][0-9][0-9] | zstd -d | tar -x --acls --xattrs --numeric-owner -C ~/restored/code
# зашифрованный:
cat projA.tar.zst.age.[0-9][0-9][0-9] | age -d -i age.key | zstd -d | tar -x --acls --xattrs --numeric-owner -C ~/restored/code
```

При распаковке от обычного пользователя владельцы файлов станут вашими (смена владельца недоступна без прав root); для системных путей `restore.sh` использует `sudo`.

## 8. Telegram

### 8.1. Почему аккаунт, а не бот

Bot API принимает файлы до 50 МБ. MTProto-клиент от личного аккаунта (Telethon) принимает файлы до 2 ГБ (утилита режет тома до 1800 МБ). Для входа нужны `api_id` и `api_hash` с my.telegram.org.

### 8.2. Вход

`./backup.sh tg login` (или кнопка в TUI): телефон → код из Telegram → пароль 2FA (если включён). Сессия сохраняется в файл с правами `600`, повторно входить не нужно. Файл сессии даёт доступ к аккаунту, храните его так же, как пароль.

### 8.3. Группа и топики

1. Создайте группу и включите «Темы» (Topics): группа станет форумом.
2. Создайте по топику на каждую директорию. Удобно называть топик так же, как папку, только с заглавной буквы.
3. `./backup.sh tg groups` покажет группы (`forum` — подходящие), `./backup.sh tg topics` — топики и их id. То же есть в TUI.

**Как директория находит топик** (одинаково в загрузчике и в TUI):

1. Запись в `[topics]` (ключ сравнивается с именем папки без учёта регистра).
2. Иначе — топик, чьё название совпадает с именем папки. При сравнении игнорируются регистр, ведущая точка, пробелы, `_` и `-`: папки `code`, `.config`, `local-share` найдут топики «Code», «Config», «Local share».
3. Если подходят несколько топиков — ошибка с перечнем, нужна явная запись в `[topics]`. Если не подходит ни один — ошибка для этой директории.

Топики определяются **до первой отправки**. Для полного бэкапа любая ошибка определения останавливает запуск до отправки чего-либо.

Названия топиков берутся из метода `messages.getForumTopics`. Если установленная версия Telethon его не содержит, утилита собирает названия из сервисных сообщений группы (медленнее) и советует обновить Telethon.

### 8.4. Загрузка

Для каждой директории по порядку:

1. тома, отсортированные по имени, как **документы** (без сжатия Telegram), с подписью `имя — N из M` и `sha256:<хэш>`;
2. файл `<имя>.sha256`, затем `MANIFEST.txt`: если они есть в топике, набор загружен целиком;
3. метка (см. [раздел 9](#9-метки-autoback)).

Показывается прогресс (процент, МиБ, скорость, оценка времени). После отправки проверяется, что размер файла на стороне Telegram совпадает с локальным.

### 8.5. Устойчивость

| Ситуация | Поведение |
|---|---|
| `FloodWait` / SlowMode | ждёт указанное время плюс 2 с и продолжает; попытка не расходуется |
| обрыв соединения, ошибки RPC | до 8 повторов с нарастающей паузой (5·2ⁿ с, не больше 300 с); **том загружается заново с начала** |
| фатальные ошибки (нет прав записи, топик закрыт или удалён, неверный id) | сразу останавливает запуск с понятным сообщением |
| перезапуск | уже загруженные тома пропускаются по журналу |
| том > 2000 МиБ | отказ до начала загрузки: пересоберите с меньшим `--volume-size` |

**Журнал** — `.state/uploaded.jsonl`: ключ (`группа|топик|папка/файл`) и `sha256`. Том пропускается, если запись с тем же `sha256` уже есть. Пересобранный архив имеет другой `sha256` и загрузится снова (старые сообщения в чате остаются: удалять их нужно вручную).

### 8.6. Подтверждения и удаление

- Если имя папки похоже на «секретное» (`ssh`, `gnupg`, `token`, `passw`, `aws`, `kube`, `.config`, `mozilla`, …), а архив не зашифрован, утилита спросит подтверждение. Флаг `--yes` пропускает этот вопрос.
- `--delete-after-upload` удаляет **локальные тома** только тех файлов, которые отмечены в журнале как загруженные. Выключено по умолчанию, спрашивает подтверждение (если нет `--yes`). `sha256` и `MANIFEST.txt` остаются.

### 8.7. Скорость и лимиты

Telethon загружает одним потоком; `cryptg` ускоряет шифрование протокола, но не делает загрузку многопоточной. Ожидайте скорость заметно ниже пропускной способности канала. Telegram ограничивает частоту запросов (`FloodWait`) и может ограничить аккаунт при злоупотреблении: не запускайте множество параллельных загрузок.

## 9. Метки autoback

Метки делают чат журналом событий.

**Полный бэкап** — выбраны **все** директории из `backup.conf` (команда без имён, или имена покрывают весь конфиг):

1. в начале в **топик логов** (`[autoback] log_topic`) уходит `{date} autoback#{n}`, например `07.11.2026 autoback#12`;
2. после тома, `sha256` и манифеста каждой директории в **её топик** уходит `autoback#{n}`.

**Частичный бэкап** — одна или несколько директорий: после архивов каждой директории в её топик уходит только дата (`07.11.2026`). Топик логов и счётчик не затрагиваются, больше нигде ничего не пишется.

Правила:

- `{date}` — **дата создания** бэкапа из `MANIFEST.txt` (`DATE`), формат `date_format`. В полном бэкапе берётся самая поздняя из дат директорий.
- Номер `n` хранится в `.state/autoback.json` (`last` — последний завершённый, `current` — текущий). Он увеличивается на единицу после **завершённого** полного бэкапа.
- Если полный бэкап прервался (ошибка, Ctrl+C, обрыв), `current` сохраняется: повторный запуск **продолжает тот же номер**, не дублируя уже отправленные метки. `--fresh` отбрасывает незавершённый и берёт следующий номер.
- Полный бэкап без настроенного топика логов не начинается.
- Если часть директорий не собралась, `backup.sh all` выгружает остальные как частичный бэкап (без `autoback#N`) и сообщает об этом.
- Повторный полный запуск, когда всё уже загружено, не загружает файлы повторно, но получает новый номер: это новая «точка» только из меток.

Форматы сообщений меняются в `[autoback]` (`log_message`, `dir_message`, `date_format`); в шаблонах доступны `{date}` и `{n}`.

## 10. Терминальный интерфейс

`./backup.sh tui` (или `.venv/bin/python tui.py`). Все изменения хранятся в памяти до сохранения (`Ctrl+S`); при выходе с несохранёнными изменениями интерфейс спросит, что делать. Перед записью конфигурация проверяется; ошибки показываются списком и ничего не записывается.

| Вкладка | Файл | Замечания |
|---|---|---|
| Источники | `backup.conf` | при сохранении старый файл копируется в `backup.conf.bak`; **комментарии не сохраняются** (шапка с описанием формата добавляется заново) |
| Топики | `telegram.toml` (`[topics]`, `[autoback].log_topic`) | список топиков загружается из группы по кнопке |
| Telegram | `telegram.toml` (`[telegram]`) | `api_hash` скрыт точками; сессия по умолчанию — `.secrets/tg.session` |
| Параметры | `backup.env`, `telegram.toml` (`[autoback]`) | в `backup.env` посторонние строки и комментарии сохраняются |
| Исключения | `excludes.txt` | файл создаётся при первом изменении, `excludes.default.txt` не трогается |
| Запуск | — | собирает команду `backup.sh`, сохраняет конфиг, на время работы уступает терминал |

`telegram.toml` перезаписывается целиком в обычном формате (комментарии не сохраняются), права — `600`.

**Клавиши:** `Ctrl+S` сохранить, `Ctrl+Q` выйти, `F1` справка; на вкладке «Источники» — `a` добавить из дерева, `p` добавить по пути, `e` изменить, `d` удалить; на вкладке «Топики» — `t` назначить топик. Кнопки дублируют клавиши.

**Дерево каталогов.** Enter по папке подставляет путь в поле ввода, «Добавить» подтверждает. Кнопки `~` и `/` меняют корень дерева; путь можно вписать вручную.

**Вкладка «Запуск».** Режим (`build` / `upload` / `all`), раскладка (как в конфиге / `--items` / `--whole`), флаги и список директорий. Если выбраны все, получится полный бэкап; если часть — частичный. Строка «Команда» показывает, что будет выполнено. Во время работы `backup.sh` интерфейс скрывается, чтобы вы могли ввести пароль `sudo` и видеть прогресс; после Enter он возвращается.

## 11. Справочник командной строки

### backup.sh

```
backup.sh [РЕЖИМ] [ОПЦИИ] [ИМЯ|ПУТЬ ...]
```

| Режим | Действие |
|---|---|
| `build` | собрать архивы (по умолчанию) |
| `upload` | загрузить собранное; без имён — все директории из конфига |
| `all` | собрать и загрузить; без имён — полный бэкап |
| `list` | показать разобранный конфиг |
| `tui` | запустить интерфейс |
| `tg …` | передать аргументы в `tg_upload.py` |

| Опция | Действие |
|---|---|
| `-n`, `--dry-run` | ничего не писать; показать план, размеры и место; для `upload`/`all` — план загрузки |
| `--whole` | вся директория одним архивом |
| `--items` | каждый элемент — свой архив (перекрывает `whole` из конфига) |
| `--single` | без нарезки на тома |
| `--split` | нарезка на тома (по умолчанию) |
| `--volume-size РАЗМЕР` | размер тома, например `1000M` |
| `--level N` | уровень zstd 1–19 |
| `--encrypt` | шифровать все архивы запуска |
| `--config ФАЙЛ`, `--excludes ФАЙЛ` | другой список директорий или исключений |
| `--no-space-check` | не прерываться, если «в худшем случае» не хватает места |
| `--delete-after-upload` | удалить локальные тома после выгрузки |
| `--fresh` | начать новый номер autoback |
| `-y`, `--yes` | не задавать вопросов |
| `-h`, `--help` | справка |

`ИМЯ` — имя папки архива из конфига; `ПУТЬ` вне конфига — разовая директория (имя берётся из пути).

**Коды возврата:** `0` — успех; `1` — были ошибки (сборки, загрузки, проверки); `130` — прервано пользователем.

### restore.sh

См. [раздел 7](#7-восстановление). Коды возврата: `0` — успех, `1` — ошибка (в том числе несовпадение `sha256`).

### tg_upload.py

```
tg_upload.py [--config telegram.toml] КОМАНДА
```

| Команда | Действие |
|---|---|
| `login` | вход в аккаунт, сохранение сессии |
| `groups` | список ваших супергрупп (`forum` / `group`) |
| `topics [--group ID]` | список топиков группы и готовые строки `[topics]` |
| `upload [ИМЯ…] [--full] [--fresh] [-n] [--delete-after-upload] [-y]` | загрузка; без `--full` метки частичные (только дата) |

`backup.sh` сам решает, полный ли бэкап, и передаёт `--full`; при прямом запуске `tg_upload.py upload` укажите `--full` сами.

## 12. Безопасность

**Что защищено**

- Источники только читаются. `tar` не получает прав записи в них, ничего не удаляется.
- Файлы утилиты создаются с `umask 077`; `telegram.toml` и `backup.env` — `600`, `.secrets/` — `700`.
- Рабочая папка утилиты исключается из архивов, поэтому ключи и сессия не попадают в бэкап.
- Белый `.gitignore` и явные запреты не дают закоммитить секреты.
- Значения `backup.env` проверяются на подстановку команд.

**Что вне защиты и на что обратить внимание**

- Чаты Telegram не имеют сквозного шифрования. Всё, что уходит без `encrypt`, доступно Telegram. Шифруйте ключи, токены, пароли, профили браузеров, `.config`, `/etc`, если там есть секреты.
- `api_hash` и сессия эквивалентны доступу к аккаунту. Не публикуйте их, не пересылайте, включите 2FA.
- Потеря ключа `age` необратима.
- `backup.log` содержит пути и имена файлов; не делитесь им без проверки.
- Флаг `--yes` отключает предупреждение о незашифрованных «секретных» папках и подтверждение удаления томов.
- Права `sudo` нужны только для чтения системных путей. Проверьте `backup.conf`, прежде чем запускать сборку.

Сообщить об уязвимости: [SECURITY.md](../SECURITY.md).

## 13. Диагностика

| Симптом | Причина и решение |
|---|---|
| `Сессия не авторизована` | выполните `./backup.sh tg login` (или «Войти» в TUI) |
| `Не нашёл группу …` | `group` — это id вида `-100…`, `@username` или точное название; проверьте `tg groups` |
| `Эта группа не форум` | включите «Темы» в настройках группы |
| `топик не найден` для директории | нет топика с таким названием и нет записи в `[topics]`; создайте топик или назначьте в TUI |
| `несколько топиков подходят` | названия отличаются только регистром или разделителями; укажите id в `[topics]` |
| `Полный бэкап не начат` | не настроен `[autoback] log_topic` или не найден топик логов |
| `FloodWait` в логе | норма: утилита ждёт и продолжает |
| `… не проходит в Telegram` | `VOLUME_SIZE` ≥ 2000M; уменьшите |
| `Нужно X, свободно Y` | места может не хватить: расширьте исключения, освободите диск или `--no-space-check` |
| `tar … код 1` | файлы менялись во время чтения; архив создан, при необходимости повторите |
| `tar … код 2` | ошибка чтения (права, исчезнувшие файлы); для системных путей используйте `sudo` |
| `Имя … зарезервировано` | задайте имя явно: `~/docs \| my-docs` |
| `Уже запущен другой экземпляр` | идёт другая сборка; если процесса нет, удалите `.state/lock` |
| `Не установлен telethon/textual` | `python -m venv .venv && .venv/bin/pip install -r requirements.txt` |
| в TUI нет списка топиков | проверьте вкладку Telegram: «Проверить», затем «Загрузить топики» |
| контрольные суммы не совпали | том повреждён или скачан не полностью; скачайте заново |

## 15. FAQ

**Нужна ли мне именно форумная группа?** Да: топики существуют только в группах с включёнными «Темами».

**Можно ли использовать канал или личный чат?** Не поддерживается: для каждой директории нужен свой топик форумной группы.

**Почему сообщения-метки не в общем топике?** Метки полного бэкапа идут в отдельный топик логов, чтобы не смешиваться с архивами.

**Почему архив `code` занимает меньше, чем папка?** Сжатие `zstd` и исключения (`node_modules`, кэши). Шифрование размер не уменьшает и не увеличивает заметно. Сравните `RAW_BYTES` и `ARCHIVE_BYTES` в `MANIFEST.txt`.

**Как не потерять данные при смене системы?** Проверьте восстановление заранее: `./restore.sh <папка> --test`, и храните ключ `age` отдельно.

**Можно ли загрузить уже существующие архивы?** Да: `./backup.sh upload` загружает всё, что собрано; журнал не даст отправить дубликаты.

**Как убрать старые тома из чата?** Утилита не удаляет сообщения Telegram. Удаляйте вручную.

**Что произойдёт при смене имени топика?** Автоматическое сопоставление найдёт новое название. Записи в `[topics]` продолжают работать по id.
